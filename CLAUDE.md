# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Not a conventional codebase: `skills/` holds six packaged Claude/Agent **Skills** for Polish and EU legal work, each shipped as a `.skill` file. There is no build system, no top-level test runner, no git history and no README. A `.skill` file is a plain ZIP with one top-level directory named after the skill, with `SKILL.md` at its root.

| Archive | Purpose |
|---|---|
| `analiza-fto` | Freedom-to-Operate / patent clearance (PL/EU, B2B). Python report generator |
| `analiza-kontradyktoryjna` | Adversarial analysis of legal arguments (plays opposing counsel). Python extraction/validation and a Node DOCX generator |
| `analiza-rozumowania` | v3.0 logical-structure analysis of Polish legal texts using the deterministic GTMØ engine (Python `lib/` and a Node DOCX report generator) |
| `eu-pl-law-tracker` | Status of EU acts and the Polish acts implementing them, from official sources (EUR-Lex, ISAP, RCL). Small CLI scripts and unit tests |
| `legal-abduction` | Competing hypotheses and an evidence matrix from documents. Python ≥3.12 stdlib only. **Evaluation preview, synthetic cases only** |
| `szukaj-orzeczen` | Court-judgment search over SAOS API and orzeczenia.nsa.gov.pl, with a thematic report |

## Working with the archives

- Inspect or edit by extracting into a **new, empty directory** (for example the scratchpad). Do not run scripts from inside an extracted archive, because Python loads modules from the working directory. Run Python with `-I` or `-B -X utf8`.
- After editing, **repack** so the single top-level directory name matches the skill name, and replace the `.skill` file. Edits to extracted copies are lost otherwise. Do not nest `skill/skill/`.
- `SKILL.md` frontmatter (`name`, `description`) drives skill triggering. The `description` lists the trigger phrases and the "do NOT use for" routing between skills, so keep it consistent when editing. Skills cross-reference each other (for example `/analiza-umow`, `/szukaj-orzeczen`, `/analiza-rozumowania`).
- Content is in Polish. Keep new skill text, report output and legal terminology in Polish, as the existing files do.

## Commands (run on an extracted skill)

```bash
# Unzip
python -c "import zipfile;zipfile.ZipFile('skills/X.skill').extractall('<new-dir>')"

# eu-pl-law-tracker: scripts and tests
python scripts/eu_law_identify.py --query "CBAM" --aliases references/regulation-aliases.yaml
python scripts/eu_law_parse.py --input-file act.txt
python -m unittest discover tests            # single file: python -m unittest tests.test_eu_law_parse

# analiza-rozumowania (needs numpy, scipy; npm i -g docx for the report)
python lib/classify_segment.py validate      # lexicon harness: expect 209 tests, 0 failures
python lib/hash_utils.py                     # each lib module has a self-test; also embed_text, segment_text, lemmatize_text, classify_segment
python lib/run_pipeline.py --text "..." --output r.json --pretty
node lib/generate_report.js r.json out.docx
# Same input must give the same meta.output_hash. Changing the lemmatizer backend (spaCy vs naive_stemmer) changes algorithm_fingerprint on purpose.

# legal-abduction (stdlib only; PowerShell env as in docs/installation.en.md)
python -B -X utf8 scripts/package_preview.py --check <zip> --smoke
python la.py ...                             # CLI entry; the command map is in references/workflow.md

# szukaj-orzeczen (needs python-docx)
python scripts/szukaj_orzeczen.py "<FRAZA>" ...
python scripts/saos_fetch.py ...
python scripts/nsa_scraper.py "<FRAZA>" --search-only --max-results 1 --skip-docx
python scripts/raport_tematyczny.py ...
```

`analiza-fto` has `scripts/generate_fto_report.py`. `analiza-kontradyktoryjna` has `scripts/ekstrakcja_argumentu.py`, `scripts/walidacja_cytowan.py` and `scripts/generuj_raport_docx.js` (Node `docx`). Check the relevant `SKILL.md` for their arguments.

## Architecture notes

- **Skill layout convention**: `SKILL.md` is the operating instruction. `references/` holds domain knowledge loaded on demand. `scripts/` or `lib/` holds deterministic helpers. `templates/` and `assets/` hold report templates. The model does the legal reasoning and the scripts do verification, extraction and DOCX generation.
- **Reports**: most skills end in a DOCX report (font Aptos), generated by Python `python-docx` or Node `docx`. Some also emit Markdown and a SHA-256 fingerprint.
- **`analiza-rozumowania`**: `run_pipeline.py` chains `segment_text` → `lemmatize_text` → `embed_text` → `classify_segment` (rules in `leksykon.json`, which embeds its own test fixtures) → GTMØ metrics, then `hash_utils` produces the four-level hashes. The pipeline is deterministic by design, so any change must keep the hashes reproducible. Embeddings use a deterministic char-n-gram MD5 fallback, with optional HerBERT.
- **`legal-abduction`**: package `legal_abduction/` follows a staged pipeline (init → ingest → extract → families → proposals → human review → observations → hypotheses → matrix → test plan → report), backed by a SQLite schema (`schemas/sql/001_core.sql`) and JSON schemas. Design invariants:
  - The agent only *proposes*; a human reviews and approves outside the agent session.
  - Quotes must be literal slices of passage text.
  - A missing assessment is `not_assessed`, never neutral.
  - The integrity chain is tamper-evident only.
  - Keep case data outside the skill directory.
- **Legal-source discipline**: the skills require official sources (ISAP, EUR-Lex, SAOS, NSA, RCL), and `cytat-check` style verification of citations. Results are advisory material for a lawyer or patent attorney, not legal advice.
